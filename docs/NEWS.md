# AI вести (агрегатор)

Страницата **/vesti** и блокот „AI вести“ на почетната собираат наслови за вештачка
интелигенција од македонски (и други) технолошки портали преку нивните **RSS/Atom фидови**.
Не се копираат целите текстови: се зачувува само **наслов, краток извадок (до 280 знаци),
датум и линк** до оригиналот, а секоја вест јасно го наведува изворот.

## Како работи

1. Табела `news_sources` – листа на извори (име, сајт, URL на фидот, јазик,
   „само AI вести“, активен/неактивен, статус на последното читање).
2. Edge Function `fetch-news` (Deno) ги чита активните фидови, ги парсира
   (`supabase/functions/_shared/feed.ts`), а кај изворите со вклучен филтер ги задржува
   само вестите што спомнуваат AI (вештачка интелигенција, ChatGPT, OpenAI, Gemini, Claude,
   LLM, машинско учење, четбот…).
3. Функцијата `ingest_news` (само за `service_role`) ги внесува: дупликати по URL се
   прескокнуваат, датуми во иднина се сведуваат на „сега“, вести постари од 365 дена се бришат.
4. Јавно се читаат преку `api_news` и `api_home` (RLS: само активни извори и нескриени вести).

## Поставување (продукција)

1. Миграцијата `20261103090000_news_and_home.sql` се применува со `supabase db push`.
   `seed_growth.sql` додава еден почетен извор: **IT.mk** (`https://it.mk/feed/`).
   **Провери го URL-то на фидот** пред објава (отвори го во прелистувач) – ако се
   разликува, поправи го во Админ → AI вести.
2. Објави ја функцијата (ја користи истата тајна `CRON_SECRET` како и известувањата):

```bash
supabase secrets set CRON_SECRET=... SITE_URL=https://www.tvojdomen.mk
supabase functions deploy fetch-news --no-verify-jwt
```

3. Закажи читање на секој час (Database → Extensions: `pg_cron` и `pg_net`):

```sql
select cron.schedule('fetch-news', '17 * * * *', $$
  select net.http_post(
    url := 'https://<ref>.supabase.co/functions/v1/fetch-news',
    headers := jsonb_build_object('x-cron-secret', '<CRON_SECRET>')
  );
$$);
```

4. Админ → **AI вести**: „Освежи сега“ ги чита сите извори веднаш, „Тестирај“ само еден.
   Тука се гледа статусот (✔ / грешка) и времето на последното читање, а поединечни вести
   може да се скријат.

Статичките страници (`/vesti`, почетна) се генерираат при build; вестите што ќе пристигнат
потоа се вчитуваат на клиентската страна при следна навигација. За свежи вести и во
статичкиот HTML, закажи повторен build (на пр. Vercel Deploy Hook еднаш дневно).

## Додавање извори

Админ → AI вести → **Нов извор**. Потребни се име, адреса на сајтот и URL на RSS/Atom
фидот (најчесто `/feed/`, `/rss` или `/atom.xml`; WordPress сајтовите имаат `/feed/`).
За портали што пишуваат за сè (IT.mk, Smartportal, Telegraf…) остави го вклучено
„само AI вести“; за сајтови посветени само на AI може да се исклучи.

## Правни и етички правила

- Користи само **јавни фидови** што сајтот сам ги објавува. Не се пребаруваат HTML страници
  (нема „scraping“), па нема заобиколување на robots.txt или пејвол.
- Прикажи само наслов, краток извадок и линк; читателот оди на изворот за целиот текст.
- Ботот се претставува со User-Agent `AI-KATALOG-NewsBot/1.0 (+<SITE_URL>/za-nas)`.
- Ако некој издавач побара, исклучи го изворот (Админ → AI вести → Измени → неактивен)
  или избриши го – со бришењето се бришат и неговите вести.
- Не се обработуваат податоци за посетители.

## Локално тестирање

```bash
./scripts/local-db.sh --publish-seed
# Внеси вести од тест-фајл (без интернет) за изворот со даден feed_url:
npm run news:fetch -- --file tests/e2e/fixtures-feed.xml --feed https://it.mk/feed/
# Или прочитај ги вистинските фидови (ако мрежата дозволува):
npm run news:fetch
```

Парсерот е покриен со unit тестови (`supabase/functions/_shared/feed.test.ts`), а
безбедноста на табелите со `supabase/tests/security_test.sql` (дел 10).
